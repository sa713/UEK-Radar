# Радар эксперта УЭК — версия для собственного сервера

Портал для экспертов: внешние источники, аналитические карточки на русском и английском, персонализация по оценкам и настройкам, сохранённое и прочитанное, редакторская проверка, демонстрационная загрузка внутренних файлов, недельный обзор и персональная рассылка Telegram.

## Архитектура

- **Web:** Next.js 16 / Node.js 24. Telegram Login, API, редактор и пользовательская лента. Открытие сайта не запускает сбор источников: читатель сразу получает сохранённую ленту.
- **Хранилище:** SQLite в WAL на локальном Docker volume; один файл базы, миграции при старте. Загруженные демонстрационные файлы лежат в том же volume, вне публичной директории. Исходные PDF/DOCX/PPTX/Markdown не выдаются читателям — публикуются подготовленные и проверенные карточки.
- **Worker:** лёгкий процесс без собственной базы. Раз в минуту проверяет расписание из базы. По умолчанию сбор новостей начинается ежедневно в 05:00 по Москве; редактор может выбрать конкретные дни недели и время. Каждый источник обрабатывается отдельно, прогресс и итоги сохраняются в базе; после прерывания сбор продолжится. По понедельникам после 08:00 Москвы создаёт недельный выпуск и доставляет его через Telegram; если сбор в понедельник назначен позже, обзор ждёт его завершения. Уже отправленные сообщения повторно не отправляются.
- **Caddy:** дополнительный профиль `proxy` для HTTPS. По умолчанию не запускается; способ публикации и порт на сервере выбираются отдельно.
- **OpenAI API:** анализ и перевод материалов. Ключ оплачивается и предоставляется отдельно от подписки ChatGPT.

```
Интернет → Caddy → Web ↔ SQLite / uploads
                     ↑
              Telegram webhook
Worker → внутренний /api/job → Telegram / OpenAI
```

Расчёт на один небольшой Debian-сервер. Приложение не использует Cloudflare D1/R2 и не требует внешнего сервера базы данных. Рабочие данные и секреты не входят в Git.

## Установка на Debian

Для установки нужен `openssl`. Docker Engine с Compose plugin потребуется при ручном запуске. Для работающего Telegram Login понадобится домен с HTTPS, Telegram-бот и отдельный ключ OpenAI API. В BotFather задайте домен входа бота точно по домену радара. Порт и подключение к обратному прокси настраиваются на сервере после установки.

Клонируйте репозиторий и запустите установщик:

```sh
git clone https://github.com/sa713/UEK-Radar.git && cd UEK-Radar && sudo bash install.sh
```

Установщик спросит домен, username бота, Telegram username администратора, новый токен бота и ключ OpenAI API. Пароли для сессий он создаст сам, а секреты запишет только в `/etc/uek-radar/keys.env` с правами `0600`. Код окажется в `/opt/uek-radar`. Установщик не выбирает порт, не запускает контейнеры и не подключает Telegram webhook. Самодостаточный `uek-radar-installer.run`, собранный командой `bash scripts/build-installer.sh`, выполняет ту же подготовку без клонирования репозитория.

При повторном запуске существующий файл ключей сохраняется. Предыдущая версия кода переносится в каталог `/opt/uek-radar.previous.<дата>`; Docker volume с базой и файлами остаётся прежним. Если в старом key-файле ещё нет `ADMIN_TELEGRAM_USERNAME`, установщик спросит его и добавит.

### Настройка порта и ручной запуск

Основной `compose.yaml` не публикует порт наружу. В `deploy/compose.port.yaml.example` есть дополнительная конфигурация для привязки сайта к `127.0.0.1` на порту, который вы выберете на сервере. Например, после выбора свободного порта:

```sh
cd /opt/uek-radar
sudo env RADAR_PORT=18080 docker compose -f compose.yaml -f deploy/compose.port.yaml.example up -d --build
sudo docker compose ps
```

Значение `18080` здесь только пример; замените его выбранным портом и настройте HTTPS через существующий обратный прокси. Контейнер `caddy` находится в отдельном профиле `proxy` и не запускается этой командой. Если понадобится собственный Caddy, его можно включить отдельно после настройки портов. Когда HTTPS-домен начнёт отвечать, подключите Telegram webhook:

```sh
cd /opt/uek-radar
sudo docker compose exec -T web node scripts/setup-bot.mjs
```

### Ручная настройка ключей без установщика

Если вы не используете установщик, создайте key-файл сами:

```sh
sudo install -d -m 700 /etc/uek-radar
sudo install -m 600 -o root -g root deploy/keys.env.example /etc/uek-radar/keys.env
sudoedit /etc/uek-radar/keys.env
```

Заполните `DOMAIN`, `SITE_ORIGIN`, `TELEGRAM_BOT_USERNAME`, `TELEGRAM_BOT_TOKEN`, `ADMIN_TELEGRAM_USERNAME` (например `srgld`, без `@`), `OPENAI_API_KEY`. Сгенерируйте **два разных** значения `SESSION_SECRET` и `CRON_SECRET` командой `openssl rand -hex 32`. Файл должен оставаться с правами `0600`; не копируйте реальные значения в исходники, issue и логи.

После старта администратор входит через Telegram. Адрес `SITE_ORIGIN` обязан быть HTTPS и соответствовать домену виджета. Источники проверяются по серверному расписанию, по умолчанию ежедневно в 05:00 по Москве. Редактор меняет дни и время в разделе «Автоматический сбор новостей» и видит результат последнего запуска. Если сервер был недоступен в назначенное время, сбор начнётся после восстановления в тот же московский день. Уже выполненный запуск за день не повторяется при изменении настроек. Для ручной проверки отдельного источника используйте редакторские средства сайта.

Для обновления кода повторно запустите `sudo bash install.sh` из свежего клона; затем вручную пересоберите и запустите контейнеры выбранной выше командой. Миграции применяются автоматически и по порядку; данные volume сохраняются. Перед обновлением сделайте копию базы.

## Резервные копии

SQLite online backup создаёт согласованную копию при работающем сервисе:

```sh
docker compose exec -T web node scripts/backup.mjs /data/radar-backup.sqlite
container=$(docker compose ps -q web)
docker cp "$container:/data/radar-backup.sqlite" ./radar-backup.sqlite
chmod 600 ./radar-backup.sqlite
```

Сохраните копию вне сервера; дополнительно копируйте `/data/uploads` из Docker volume, если в нём есть файлы, которые нужно сохранить. Для восстановления остановите `web` и `worker`, замените базу в volume копией и запустите сервисы. Файл ключей `/etc/uek-radar/keys.env` резервируйте отдельно в защищённом хранилище.

## Перенос данных с текущего сайта

Этот репозиторий переносит функционал. База нового сервера начинается пустой; исходная база Cloudflare D1 и файлы R2 автоматически не копируются. Для переноса существующих карточек, предпочтений, источников и выпусков нужен отдельный экспорт данных из текущего проекта с сохранением ID и проверкой персональных данных. Импортируйте записи после установки схемы, затем переключите домен и webhook. До переключения нынешний сайт может работать параллельно.

## Разработка

`pnpm install`, затем `pnpm db:migrate`, `pnpm dev`. Локальные данные лежат в `./data`, серверный путь задаётся `DATABASE_PATH`. Для полноценного входа нужен HTTPS-домен и заполненный файл переменных окружения; в разработке можно передать его через менеджер окружения, не помещая в репозиторий. `pnpm typecheck` и `pnpm build` проверяют приложение. Версии зависимостей закреплены в `pnpm-lock.yaml`.

## Границы доступа

Telegram Login пускает любого пользователя. Роль редактора назначается по `ADMIN_TELEGRAM_USERNAME` из серверного key-файла; сравнение не зависит от регистра и допускает `@` перед именем. После ручного изменения key-файла пересоздайте контейнер `web` командой `docker compose up -d --force-recreate web` и войдите снова. Сессия администратора длится не более 12 часов, поскольку Telegram username может меняться и переходить другому человеку. Внутренние файлы загружает редактор, полученные карточки сначала попадают на проверку. Загрузка банковских файлов в этом демонстрационном проекте не предполагается: перед реальным использованием нужен отдельный согласованный контур защиты и хранения данных.

# HTTPS по IP рядом с существующей галереей

Установщик принимает полный URL, например `https://203.0.113.10:8443`, и задаёт `TELEGRAM_LOGIN_MODE=device`. Код и ключи устанавливаются без запуска контейнеров. Секреты лежат в `/etc/uek-radar/keys.env`; их нельзя отправлять в Git.

Прокси радара из `compose.ip.yaml` публикует только выбранный HTTPS-порт. Внутри контейнера Caddy слушает 8443. Для сертификата IP используется Let’s Encrypt с профилем `shortlived` и HTTP-01: внешний запрос проверки приходит на TCP 80. Существующий Caddy должен передавать только путь `/.well-known/acme-challenge/*` для IP в `uek-radar-ip-proxy:80`; доменные блоки галереи сохраняются. Образ Caddy закреплён на 2.11.4; сертификат продлевается автоматически, поэтому этот маршрут должен оставаться доступен.

Перед настройкой определите Docker-сеть существующего Caddy:

```sh
docker inspect photo-gallery-caddy-1 --format '{{range $name, $settings := .NetworkSettings.Networks}}{{println $name}}{{end}}'
```

Сделайте резервную копию Caddyfile галереи и добавьте блок из `gallery-challenge.Caddyfile.example`, заменив пример IP своим. Проверьте файл в существующем контейнере командой `caddy validate --config /etc/caddy/Caddyfile --adapter caddyfile`. Применяйте через `caddy reload`, сохраняя работающий контейнер. Если проверка завершилась ошибкой, восстановите копию; не перезапускайте галерею.

После подготовки маршрута вручную запустите радар. Замените пример IP, порт и имя сети значениями сервера:

```sh
cd /opt/uek-radar
sudo env RADAR_IP=203.0.113.10 RADAR_HTTPS_PORT=8443 GALLERY_NETWORK=photo-gallery_default docker compose -f compose.yaml -f deploy/compose.ip.yaml up -d --build
```

Дополнительный прокси подключается к существующей сети галереи под именем `uek-radar-ip-proxy`, а к web — через собственную сеть радара. Проверьте логи `ip-proxy` и доступность выбранного HTTPS-порта в межсетевом экране. Браузер должен принять сертификат без предупреждения; публичное получение сертификата проверяется только на реальном сервере. Порт 3000 веб-приложения наружу не публикуется.

После запуска вручную подключите бота:

```sh
cd /opt/uek-radar
sudo docker compose exec -T web node scripts/setup-bot.mjs
```

В режиме `device` команда удаляет старый webhook, не удаляя ожидающие сообщения. После этого worker принимает сообщения бота; старый сайт перестанет получать его webhook. Не запускайте два polling-потребителя одного токена. Пользователь нажимает кнопку входа на сайте, сверяет код у бота, подтверждает его и возвращается в исходный браузер. Код нельзя подтверждать по ссылке, присланной другим человеком.

Для повторного запуска используйте ту же команду с `compose.ip.yaml` и теми же переменными. Проверка контейнеров и журналов также должна включать этот override. Установщик по-прежнему не выбирает порт и не запускает сервисы сам.

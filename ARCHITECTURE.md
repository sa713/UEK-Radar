# Решения по переносу

| Область | Реализация | Основание |
|---|---|---|
| Публикация | Next.js standalone в Docker; порт и обратный прокси настраиваются вручную на сервере, Caddy — дополнительный профиль | Сохраняет существующий интерфейс и маршруты |
| Данные | SQLite WAL в постоянном volume, миграции транзакциями | Один Debian-сервер; простое резервирование |
| Файлы | Локальный volume `/data/uploads`, UUID каталога, права 0600 | Заменяет R2; исходники не обслуживаются веб-сервером |
| Сбор новостей | Серверное расписание в SQLite: ежедневно или выбранные дни, время МСК; один источник за шаг | Не задерживает вход пользователя; переживает перезапуск и показывает результат редактору |
| Недельная рассылка | Отдельный worker, понедельник после 08:00 MSK | Не зависит от открытого браузера; повторная отправка исключена таблицей deliveries |
| Секреты | `/etc/uek-radar/keys.env` только на сервере; Docker env_file | Не попадают в сборочный контекст и Git |
| Доступ | Подпись cookie; подтверждение кода через Telegram-бота (device) либо виджет для домена; редактор по username в серверном key-файле | Права назначаются конфигурацией без изменения базы |

Следующий этап после установки: выбрать порт на сервере, подключить обратный прокси, подготовить DNS и домен бота, вручную запустить контейнеры и настроить webhook. Затем отдельно решить перенос данных из текущей D1-базы. Для 2 ГБ RAM сборка Next.js может быть тяжёлой; при необходимости собирайте образ вне сервера и доставляйте готовый образ.

IP-размещение: отдельный ip-proxy на выбранном HTTPS-порту, публичный IP-сертификат ACME shortlived; HTTP-01 проверка передаётся существующим Caddy из Docker-сети галереи. Бот в device-режиме использует long polling; смещение обработанных обновлений хранится в SQLite. Установщик не запускает контейнеры и не переключает доставку сообщений бота.
